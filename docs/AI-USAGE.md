# AI assistance

The course guidelines ask students to explain any AI-assisted code. This file says plainly what the
AI did in this project and how the result was checked.

## Tools

- **Claude (Anthropic)**, used as a coding assistant in Claude Code on 10 November 2026: one lead
  session that planned and reviewed, and separate Claude sessions it started for building and for
  adversarial review.
- **Claude (Anthropic)** again on 12–13 November 2026 for the redesign of the web interface: the new
  first screen of the planner, the `/docs` page with the three interactive labs and the evaluation
  charts, and the updated README and defense notes. One lead session and two helper sessions (one for
  the A* lab, one for the HMM and MDP labs).

The team is Tair Kaldybayev and Dameli Kalikhanova; the sessions ran on one laptop.

## What the AI produced

| Part | AI contribution |
|---|---|
| Idea | I asked for a useful, non-generic application of three course algorithms on real data. The assistant proposed the air-quality planner and the way the three algorithms feed each other. |
| Specification | [`SPEC.md`](SPEC.md) was written by the assistant, then attacked by a separate reviewer session and corrected before any code existed (for example: "skip" could never be chosen; sparse transition rows gave absurd probabilities; the road factor overclaimed what is known about PM2.5). |
| Algorithms | `tynys/hmm.py`, `tynys/mdp.py`, `tynys/astar.py` were written by the assistant from the specification, in plain Python without libraries. |
| Service, API, data | The rest of `tynys/`, `api/`, the build scripts in `scripts/` and the data files they produced from OpenStreetMap, Photon and Open-Meteo. |
| Tests and evaluation | `tests/` and `tynys/evaluate.py`, including the negative results reported in [`evaluation.md`](evaluation.md). |
| Web interface | Everything in `src/`: layout, charts, map, wording, and the `/docs` page with its labs (`src/docs/`). The labs re-implement one Bayes step, one Bellman backup and a grid A* in TypeScript; their tests check the first two against the Python results and A* against Dijkstra. |
| Documentation | README, this file, the defense notes. |

In short: the code and the text in this repository were generated by the assistant under our direction.

## How it was checked

- **Unit tests** run offline: the textbook umbrella-world values for the forward filter and Viterbi, a
  hand-solved MDP, A* on a grid with a known optimum, A* against Dijkstra on the real graphs.
- **Independent re-implementation.** A separate reviewer session rewrote the HMM, MDP and A* recursions
  from the specification without looking at the implementation's code paths and compared the numbers
  on real data and on random inputs: no mismatches. It also checked on every edge of both street graphs
  that the heuristic is admissible and consistent.
- **Mutation checks.** The same reviewer shifted time indices by one hour in four places; the tests of
  that time did not notice, so tests that pin the time alignment were added.
- **Honesty review.** Wording that claimed more than the code computes was changed: model values are
  not called measurements, the road factor is called a traffic exposure index, the route score is
  "for comparison only", and the evaluation of the decision policy reports the version without access
  to the future next to the optimistic one.
- **In the browser.** Both cities, both themes and a phone-sized screen were exercised against the
  live API before deployment.
